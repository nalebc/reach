# Reach HTTP API

Base URL: `https://computer.tailnet.ts.net:8443`. Every API endpoint requires `Authorization: Bearer TOKEN` except the ones that start or redeem access: `GET /api/health`, `POST /api/pair`, `POST /api/guest/redeem` (alias `POST /api/invitations/redeem`), `GET /api/auth/method`, `POST /api/auth/requests` and its `/:id` routes (poll, passkey challenge and passkey approval are made by the requesting browser before it has a credential), `POST /api/auth/face-join`, `POST /api/invitations/claims/:id/status` (a waiting receipt collecting its own decision), and `GET /download/:token` (a short-lived link that carries its own token). Each of those still checks Tailscale identity, rate limits or a secret of its own. Remote clients must use HTTPS. Requests and responses are JSON unless indicated. Errors have `{ "error": "message" }` and an appropriate HTTP status.

## Pairing and identity

- `GET /api/health` — product and version, no personal information.
- `POST /api/pair` — `{code, name}`. Exchanges the single-use local code for `{token, clientId, device}`. Codes expire after ten minutes; five attempts per minute per transport address. Native clients and browsers use the same API.
- `GET /api/device` — device metadata, capabilities, shared folder roots, Tailscale state.
- `GET /api/clients` — full-access browser clients only.
- `DELETE /api/clients/:id` — revoke a credential and close its open terminal sockets.

Device responses include an installation `id` and a `computerId` derived from a hash of the OS machine identity. Resetting Reach's data changes the installation ID but normally preserves the computer identity. If the OS identity cannot be read, Reach retains its saved identity or falls back to the installation ID. OS reinstalls or cloned machine identities may require manual reconciliation. Neither identifier authorizes access; pairing credentials remain required. Clients use this identity to keep one computer entry across pairings, preferring connections that successfully authenticate. Display names never determine identity, and terminal/chat sessions remain separate.

Device `capabilities` combine credential scopes with host support. `screen` means supported and viewing enabled; `screenSupported` means this OS supports screen access and the credential has screen scope. `codex` means the credential has Codex scope and a local executable is detected (cached for 30 seconds); clients also check `/api/codex/status` for account readiness before offering conversations. `tools.codex.installed` is returned only to clients with Codex scope. Capability discovery never authorizes an operation: every endpoint keeps its existing scope and lease checks.

## Files — scope `files`, or agent `files:read` / `files:write`

`root` is the numeric shared-folder ID returned by `/api/device`; default `0`. For profiled agents, these indices refer only to that credential's allowed folders. `path` is relative to that folder. URL-encode query parameters. Absolute paths, traversal outside roots, and symlinks outside roots are rejected. Companion-private data and the agent policy file are excluded. GET/HEAD require `files:read`; mutations require `files:write`. The legacy `files` scope includes both.

- `GET /api/files?root=0&path=Documents&hidden=0` — `{items, path, truncated}`. Each item includes name, path, type, size, modified. Up to 2,000 directory entries.
- `GET /api/files/text?root=0&path=Documents/example.txt` — `{text}`, up to 1 MB. Binary previews are rejected.
- `GET /api/files/icons?types=folder,pdf,docx` — `{icons: {[type]: dataUrl | null}}`: the icon the computer's own file manager shows for each type (Finder on Mac, Explorer on Windows, the desktop icon theme on Linux). Up to 64 types: `folder`, `file`, or a lowercase extension of up to 16 letters/digits. Containers and machines without an icon set return `null`, and clients keep their built-in icons. Clients cache these on the device and refresh weekly.
- `GET /api/files/document-text?root=0&path=Documents/Contract.docx` — `{text}` extracted from a `.doc`, `.docx`, `.rtf` or `.odt` file for preview and copy: on a Mac through `textutil`; elsewhere Reach reads `.docx`, `.rtf` and `.odt` itself, and a `.doc` answers 501 (download it). Documents up to 25 MB, text up to 1 MB. Read-only: the response has no `sha256`, so it can never be written back over the document.
- `PUT /api/files/text?root=0&path=notes.txt` — `{text,sha256}`. The GET response also includes `sha256`; supply that last-read value to avoid overwriting an intervening edit. Existing text files only, new text up to 128 KiB, no NUL bytes. Written in place through the one file checked (a link or another file put in its place meanwhile is refused); edits apply one at a time, and changed content returns 409.
- `GET /api/files/content?root=0&path=Documents/example.pdf` — binary attachment. Supports `Range` (206) with `If-Range`, so clients resume a dropped download only while the file is unchanged.
- `GET /api/files/download-link?root=0&path=Documents/example.pdf` — `{url, expiresIn}`: a `/download/<token>` link for the browser's own download manager. Tokens are 256-bit, in memory only, valid 10 minutes, and name one file. Each use re-verifies the issuing credential from its hash (revocation, expiry, Tailscale identity and node, guest folders, agent policy), re-resolves the path, and refuses a file modified since (410). Responses are `attachment` and `no-store`, and support `Range`.
- `POST /api/files/uploads` — `{root, path, name, size}` starts a resumable upload: `{id, offset, chunk}`. Checks the name, that it doesn't exist yet (409), and free space on the computer (507). Default limit 50 GB; at most 8 uploads at once per credential.
- `PUT /api/files/uploads/:id?offset=N` — raw bytes (`application/octet-stream`), up to 16 MB, exactly at the offset the computer has; otherwise 409 with `{offset}` to continue from. Returns `{offset}`.
- `GET /api/files/uploads/:id` — `{offset, size}`, to resume after a dropped connection.
- `POST /api/files/uploads/:id/complete` — publishes the file once every byte has arrived; never over an existing file (409); 404 if the folder no longer exists. `DELETE /api/files/uploads/:id` cancels. Upload sessions belong to the credential that started them, and partial files are removed when finished, cancelled, idle for a day, or when Reach restarts.
- `POST /api/files/upload?root=0&path=Downloads` — multipart field `file`, max 100 MB. Existing names produce 409. Hidden filenames are rejected for uploads.
- `POST /api/files/folder` — `{root, path, name}`.
- `POST /api/files/extract` — `{root, path}` (both required), returns `{name, path}` for a new folder beside the archive. Requires a paired owner **device**, `admin`, and file read **and** write access (`files` or both granular scopes). Guests, service credentials, scoped CLI agents and browser agents are refused, even if they can otherwise write files. ZIP, TAR, `.tar.gz` and `.tgz` are supported; `.tar.bz2`/`.tar.xz` return 415. Limits: 64 MiB input, 256 MiB expanded data, 64 MiB per file, 4,096 entries and 60 seconds; one extraction at a time per companion (429 while busy). Only regular files and directories are created; links, special files, unsafe paths and conflicting names are rejected. Existing destinations are preserved by choosing a new name. Access is rechecked during processing; revocation or disconnect cancels extraction and removes its temporary files when their identity is unchanged. Host processes concurrently modifying directories are outside this guarantee; extraction is not an OS sandbox. This operation is not advertised as an agent CLI/MCP tool.

## Command jobs — scope `exec`

```http
POST /api/jobs
Authorization: Bearer TOKEN
Content-Type: application/json

{"command":"git status --short","root":0,"path":"Documents/project","timeoutMs":60000}
```

Returns **202** and `{id, clientId, command, cwd, status, createdAt, output, exitCode, timeoutMs}`. Run commands only with the user's authorization. Commands run as the companion's OS user, not in a container or a filesystem sandbox.

- `GET /api/jobs` — own jobs; full-access browsers can see all.
- `GET /api/jobs/:id` — poll output/status; complete jobs include `finishedAt`.
- `DELETE /api/jobs/:id` — cancel the job/process tree.

States: `running`, `completed`, `failed`, `timed_out`, `cancelled`, `interrupted`. Timeout 1 second–1 hour; eight concurrent jobs. A restart marks formerly running jobs interrupted. Output retains the latest 256 KiB.

## Terminals — scope `terminal`

- `GET /api/terminals` — list live and exited session metadata.
- `POST /api/terminals` — `{root, path, name}`; starts a real PTY. Or `{cwd, input}` (a chat's play button): `cwd` is a full path inside a shared folder (403 otherwise), and `input` (1–8,000 characters, no control codes except tabs and newlines; not with `run`) is typed into the new shell, each line followed by Enter.
- `DELETE /api/terminals/:id` — stop its shell.

Connect to `wss://computer.tailnet.ts.net:8443/ws/terminal`. Authenticate in the **first message**, within five seconds:

```json
{ "type": "auth", "token": "TOKEN", "sessionId": "ID" }
```

Do not place tokens in URLs. Incoming: `snapshot` (buffer and status), `data` (output and sequence number), `exit` (exitCode), `error`. Outgoing after authentication:

```json
{"type":"input","data":"pwd\r"}
{"type":"resize","cols":90,"rows":28}
```

Closing the socket does not kill the terminal. Reconnect with the same session ID for a fresh snapshot. Companion restarts do end terminals. Maximum 12 running terminals; input frames up to 32 KiB.

### Existing Mac terminals — scopes `terminal` and `admin`

These endpoints control Apple Terminal tabs and iTerm2 panes outside Reach. Discovery does not launch apps and may request macOS Automation permission. The Mac terminal UI discovers on opening, refreshes the list every five seconds, and reads selected output about every 1.5 seconds. Background/hidden views pause polling. They do not attach to, resize, or replace the underlying PTY. Output is visible text only (up to 128,000 characters); input is text plus Enter. No terminal contents or sent text are added to Reach's activity log. Scoped agents cannot access these endpoints. Desktop sessions are not killed when Reach stops.

- `GET /api/terminals/desktop` — `{sessions,providers}`. Each session has opaque `id`, `provider`, `name`, and `tty`. Each provider includes its running state or a permission/error message. Re-discover after a companion restart. IDs include the native app's launch identity and tab/pane identity; titles and tab positions are not identities.
- `POST /api/terminals/desktop` — `{provider:"terminal"|"iterm2"}`. Explicitly opens a new window; may launch the selected app.
- `GET /api/terminals/desktop/:id` — `{text}` for that existing session. With `?after=<version>` (while the Mac's terminals are watched, see below): `{text,version}` at once if the text differs from that version, otherwise when the tab next prints, or `{version,unchanged:true}` after about 20 s. Start with `after=0`. A reply without `version` means the Mac isn't watching: read about once a second instead.
- `GET /api/terminals/desktop/activity?after=<version>` — `{version,peeks:{<id>:"last line"}}`: every tab's last non-empty line, answered when one changes or after about 20 s. 409 while the Mac's terminals aren't watched.
- `POST /api/terminals/desktop/:id/send` — `{text}` (1–16,000 characters; non-whitespace, no control codes except tabs/newlines). Goes to the currently running program, which may not be a shell. Do not automatically retry a send after a timeout: it may already have been delivered.
- `POST /api/terminals/desktop/:id/focus` — brings that session to the front on the Mac.
- `POST /api/terminals/desktop/:id/close` — `{confirm:true}`. Requests closing only that tab/pane. Running work can stop; closing the terminal that runs Reach also disconnects the companion. The native app may show a close confirmation on the Mac.

While a person with `admin` + `terminal` has a presence connection open, the Mac watches its Terminal and iTerm2 windows by events (`scripts/native/terminal-watch.swift`: a new tab is the app forking, a closed one its process exiting, output a write to the tab's tty). The list is then served from what was last seen, and presence `changes` carry `macTerminals`, a fingerprint that changes when tabs open, close or are renamed (agents' spinner glyphs aside); refetch the list when it changes instead of polling. Nothing is read while the terminals are idle; while tabs print, the list is looked at again at most every 5 s, and a safety look runs every minute. Without `macTerminals`, poll as before.

Only one native terminal operation runs at a time; concurrent calls receive 409. Native operations time out after 15 seconds. Revocation is checked before dispatch and before returning results; already-dispatched commands cannot be undone. Display names are never used to select a target. Unsupported hosts receive 409.

## Apps — scope `apps`

- `GET /api/apps` — installed `{id, name}` entries.
- `POST /api/apps/launch` — `{id}` from the app list. Launches on the computer's desktop.
- `POST /api/apps/icons` — owner only (`admin` and `apps`). `{ids}`, 1–64 ids from the app list. Returns `{icons: {[id]: dataUrl | null}}` with 128 px PNG logos (Mac only; `null` elsewhere). Ids that aren't installed are omitted and never reach the native reader. Concurrent requests share one native lookup. Clients keep the logos on the device and refresh them weekly.

## Codex — scope `codex`

- `GET /api/codex/status` — installed/running and signed-in state.
- `GET /api/chats` — Reach chat summaries.
- `POST /api/chats` — `{root, path, name}`.
- `GET /api/chats/:id` — transcript, status, pending approvals, errors. Poll at ~1 second while active.
- `POST /api/chats/:id/messages` — `{text}`.
- `POST /api/chats/:id/stop` — interrupt the current turn.
- `POST /api/chats/:id/approvals/:requestId` — `{decision:"accept"}` or `{decision:"decline"}` for command/file approvals; `{answers:{questionId:"answer"}}` for user questions. Never grant an approval without the user's authorization.

Unknown approval types fail closed. So do turn ends Reach does not know: a Codex `turn/completed` whose status is not `completed`, `interrupted` or `failed`, or a Claude Code `result` whose subtype is not `success` or `error_*`, leaves the chat working with its approvals in place. The MCP adapter intentionally omits approval-granting tools.

## Screen — scope `screen`, viewing must be enabled

`GET /api/screen/displays` returns the current display IDs, names, primary flag, and bounds. Requires enabled viewing and `screen` scope.

`WS /ws/screen` uses the same exact Host/Origin and Funnel restrictions as the terminal socket. Authenticate within five seconds with `{type:"auth",token:"...",protocol:2,display:"primary",quality:"balanced",format:"h264"}`. Display is `primary` or an ID from the display list; quality is `auto` (used by the UI), `saver`, `balanced`, or `smooth`; format is `h264` or `jpeg`. Optional `maxWidth` (an integer, 640–3840) is the phone's longest side in pixels: in `auto` quality the stream matches it (never beyond the display's own pixels, up to 16 Mbps), and it caps the other presets. Send `{type:"diagnostic",text}` to note why the phone's video changed; Reach logs one line per viewer every few seconds. Credentials never appear in the URL. The ready message includes the resolved display, negotiated format, target fps, width, and bitrate. Windows without FFmpeg negotiates JPEG.

Binary packets start with a uint32 big-endian sequence ID. JPEG packets contain the image after this prefix. H.264 packets contain another uint32 big-endian JSON header length, then `{key,timestamp,width,height,codec}`, then Annex B encoded bytes. Timestamps are microseconds. Keyframes contain parameter sets. ACK with `{type:"ack",id}` after admitting into a bounded decoder queue (JPEG: after drawing); use `keyframe:true` when recovery needs an IDR. Each viewer has at most six unacknowledged packets and an outgoing-buffer threshold; slow viewers resume at a keyframe. Invalid ACKs close the session; an outstanding packet times out after ten seconds. Up to four protocol-2 viewers share capture for identical display/quality/format settings. The legacy JPEG protocol remains available to old clients with its separate four-viewer limit and one-frame acknowledgment window. Frame bodies are capped at 8 MiB.

Access is rechecked before every delivered frame; expiry/revocation/disablement closes streams. Last-viewer disconnect stops that group's native capture. Errors arrive as `{type:"error",error:"..."}` followed by closure. Video grants no input permission.

`WS /ws/screen-input` requires `admin` + `screen`, enabled viewing, and a separately acquired `/api/screen/control` grant. Authenticate with `{type:"auth",token:"...",display:"42"}`. Use the display ID resolved by the video ready message. Ready includes an initial normalized cursor position when available. Ready advertises `window:8` and `typing:true` when focused typing is supported. Send up to eight unacknowledged `{type:"input",id,action}` messages with strictly increasing integer IDs. Match `{type:"ack",id,...result}` by ID: coalesced motion may be acknowledged before an earlier native action completes. Older servers without `window` require one outstanding action. The host dispatches serially, coalesces consecutive queued moves, and rejects excessive or stale queued input. A second input socket for the same client is rejected while the first is open. Close codes: `4001` ends control (its `{type:"error"}` says why: revoked, expired, taken over, paused); `1012` with `{type:"error",error,retryable:true}` asks for a reconnect (the phone's identity was being checked, or the host heard nothing for 3 s) and the control grant waits 15 s for it. Actions are:

- `move`, `down`, `up`, `click`: normalized finite `x,y` in `[0,1]`, `button: "left"|"right"`, click `count:1|2`.
- `scroll`: finite `dx,dy`, each between -120 and 120.
- `key`: letter, digit, F1–F12, navigation key, space, enter, tab, escape, backspace, or delete; unique `modifiers` from `meta,alt,control,shift`.
- `text`: UTF-8 text up to 8 KiB.
- `focus`: optional normalized `x,y` click coordinates. Returns `target:{editable:false}` or `target:{editable:true,focus,secure}` using OS accessibility metadata. Coordinates must fall within the focused field. No field contents are returned.
- `type-edit`: `{focus,delete,text}` requires the current focus token, deletes 0–256 characters by Backspace, then inserts up to 8,000 UTF-8 bytes. `key` also accepts `focus` to guard Enter/Backspace/Tab dispatch. Tokens are scoped to the native input helper; they do not replace owner authentication or the control lease.
- `selection-read`: explicitly reads the currently focused app’s accessible selected text, capped at 16 KiB; password fields are rejected. No selection/unsupported app returns an error, never stale clipboard contents.
- `clipboard-read`: returns text, capped at 16 KiB. `clipboard-write`: text up to 16 KiB. Neither is automatic.
- `release`: release held mouse buttons. `heartbeat`: keep the active control connection alive without generating input.

Successful actions renew the existing control lease; the browser sends idle heartbeats every 500 ms. Revocation/expiry are checked before and after native actions and at least every 500 ms. Idle connections close after three seconds. Native helpers release held buttons after two seconds without messages, and on normal shutdown. Payload/rate limits apply; clipboard data is never returned after a failed authorization recheck. Already-dispatched OS actions cannot be recalled.

- `GET /api/screen` — primary-display JPEG, only while screen viewing is enabled in Settings or by `REACH_SCREEN=1`, and the OS permits capture. No-store response; overlapping requests share a capture.
- `POST /api/screen/control` — `{enabled:true}` acquires/renews a 30-second input grant for the authenticated full-access paired browser. Requires `admin` as well as `screen` scope. Returns `{enabled:true,expiresAt}`; another controller receives 409. `{enabled:false}` releases the caller's grant. Renew every 10 seconds while the viewer is active. Grants are memory-only and do not survive restart.
- `POST /api/screen/input` — requires the caller's unexpired control grant plus enabled screen viewing. Accepts `{type:"click",x:0.5,y:0.5,button:"left",count:1}` (normalized coordinates; left/right; count 1 or 2), `{type:"scroll",delta:-3}` (integer -10 through 10, nonzero; positive scrolls up), `{type:"text",text:"hello"}` (max 2,000 characters), or `{type:"key",key:"enter"}`. Returns 409 while another native input operation or a persistent input channel is active. Permission is rechecked before dispatch, including after helper compilation.

Keys: enter, backspace, tab, escape, left, right, up, down. Mac capture needs Screen Recording permission; input also needs Accessibility. Windows needs an unlocked interactive desktop. No lock-screen bypass. Revoke a client or disable screen viewing to invalidate its control grant. Already-dispatched OS input cannot be undone.

### Apps on your phone — scopes `admin` + `screen`, Mac only

Each app opened on the phone runs on the Mac on its own hidden display (macOS `CGVirtualDisplay`, checked at runtime), in a window shaped like the phone. Only that window is streamed. See [Apps on your phone](APP_THREADS.md).

- `GET /api/screen/apps` — this computer's app threads, newest first: `{id,appId,name,state,createdAt}` plus, while `running`, `display`, `region:{x,y,w,h}` (the window, in display points), `size:{w,h}` (the hidden display) and `scale`. States: `starting`, `running`, `paused` (after a restart or "Return all"; reopen with POST), `closed` (the app closed its window).
- `POST /api/screen/apps` — `{appId,width,height}`: an `id` from `GET /api/apps` and the phone's usable screen in points (200–1000). Opens the app on a hidden display, or resumes its existing thread, and returns the thread. Browsers, Finder and Terminal get a new window; other apps lend their main window and get it back. Up to four threads. 404 for unknown apps, 501 off macOS, 403 with screen viewing off or without Accessibility for Reach.
- `PATCH /api/screen/apps/:id` — `{width,height}` after the phone rotates: reshapes the window (the display is already sized for both orientations).
- `POST /api/screen/apps/:id/activate` — brings the app forward on the Mac.
- `POST /api/screen/apps/:id/quit` — `{confirm}`: quits the app like ⌘Q. Returns `{confirm:true,others}` without quitting when the app also has windows on the Mac's own screens (send again with `confirm:true`), `{quit:true}` once it quit, or `{quit:false,waiting:true}` while it asks something (unsaved work); the thread ends when it quits. Apps that quit on the Mac end their threads too.
- `GET /api/screen/apps/:id/fields` — `{fields:[{x,y,w,h,secure}],complete}`: the window's visible text fields in points from its top-left (a bounded accessibility walk), so a tap on one can open the phone keyboard within the tap.
- `DELETE /api/screen/apps/:id` — gives it back: a window Reach opened is closed (if closing is blocked, it moves to the main screen instead), a lent window returns to its exact frame. Returns `{closed,returned}`.

Video: `WS /ws/screen` with `thread:"<id>"` in the auth message streams that window only, at its full Retina resolution (capped by the phone's pixels and `maxWidth`), 60 fps and up to 16 Mbps, without the pointer; the usual auto mode lowers frame rate and bitrate on a slow connection. A window change or rotation ends the stream as retryable (reconnect for the new crop); returning the app ends it for good. Input: the existing `WS /ws/screen-input` with the thread's `display`; map 0..1 window coordinates through `region` and `size`. Presence `changes` include `apps` for owners. Hidden displays are omitted from `GET /api/screen/displays`.

### Temporary guest access

- `POST /api/guests` (admin): `{name, ttlSeconds, roots: [0], folders: [{root, path}], write, screen: false | "view" | "control", apps: "all" | [ids], terminal, agents, full, key, group}`. Returns 201 with `{invitation, clientId, expiresAt, scopes, url}` and, with `key: true` (invite keys set up with `./reach invites`), the one-use Tailscale `key` and `hostname` for a guest without the Tailscale app. `roots` uses the owner's `/api/device` root IDs; `folders` are browsed subfolders inside them (up to 20). Duration is an integer from 60 to 86400 seconds. Access is exactly what was picked (`guestAccess` in `server/core.mjs`): folders read or read/write, the screen to watch or to watch and control, chosen apps' windows, their own terminals, AI sessions (`agents`), or `full` (everything but managing access). `group` carries one id for an invitation made on several computers. `POST /api/guests/:id/access` (admin) changes a guest's or agent's access later with the same checks and no new link; `folders: "keep"` keeps theirs.
- Send the guest `https://<reach-host>/guest#invite=<invitation>`. The time window starts when the invitation is created.
- `POST /api/guest/redeem` (no credential): `{invitation}`. Atomically exchanges a one-use invitation for `{token, clientId, expiresAt, device}` without extending expiry.
- `GET /api/clients` (admin) includes guest expiry, kind, and `invited`, `accepted`, or `expired` status, never invitation hashes. `accepted` means redeemed, not currently online.
- `DELETE /api/clients/:id` (admin) revokes an unused invitation or active guest.
- `DELETE /api/device/access` revokes the calling credential (guest Leave action).

`/api/device` includes `access.kind`, `access.scopes`, and `access.expiresAt`. Expired credentials return 401, including after restart. Active transfers and streams are cut off; no refresh or renewal endpoint exists. Tailscale membership is managed separately.

### Owner app shortcuts

`GET /api/apps/shortcuts` lists runnable installed-app actions, supported fixed integrations and saved custom shortcuts as `{id,name,detail,kind,suggested?,custom?}`. Only an installed app named Codex enables its built-in actions; ChatGPT alone does not. Uninstalled apps and custom shortcuts pointing to them are excluded. `POST /api/apps/shortcuts` accepts only `{id}` from this list. `codex-new` opens a fresh desktop composer through a fixed deep link; app actions launch an installed app. Website shortcuts open an explicitly saved HTTP(S) link on the computer, without shell interpolation or server-side fetching.

Custom shortcut management (all require `admin` and `apps` scopes):

- `GET /api/apps/shortcuts/custom`: saved definitions with `available` state, including unavailable apps so owners can repair or remove them.
- `POST /api/apps/shortcuts/custom`: `{name,type:"app",actionId}` or `{name,type:"website",url}`. Include an existing `id` to edit. Names are 1–60 characters; at most 50 entries are saved per computer. App actions must exist in its built-in catalog. Links are HTTP(S), up to 2,048 characters, without embedded credentials or control characters.
- `DELETE /api/apps/shortcuts/custom/:id`: remove a saved shortcut.

Definitions persist in private `shortcuts.json`; paired owners on that computer share them. Guests and scoped agents cannot list, create, edit, delete or launch these shortcuts. Authorization is rechecked after discovery and immediately before mutations/dispatch. App discovery is cached for up to 30 seconds. Shell commands, arbitrary URL schemes, app arguments and automatic prompt submission are unsupported.

## Tailscale owner approval (configured Mac/Linux launcher)

- `GET /api/auth/method` returns `method: "tailscale" | "pairing"`, `eligible`, and the verified login only to an eligible owner. It grants no resource access.
- `POST /api/auth/requests` with `{name}` creates a five-minute local approval request. Returns `{id, secret, verification, expiresAt}`. Requires verified private Tailscale ingress and the configured owner identity.
- `POST /api/auth/requests/:id` with `{secret}` polls that request from the same Tailscale node/user. Returns `{status}` or `{status: "approved", token, device}`. Keep the claimant secret out of query strings/logs. Retry the same request after a dropped response.
- Approval/denial happens locally via `./reach approve` or the foreground terminal, or with a registered passkey: `POST /api/auth/requests/:id/passkey/options` returns the challenge and `POST /api/auth/requests/:id/passkey` approves that one pending request when the assertion verifies (Face ID for new browsers in [SECURITY.md](SECURITY.md)). A linked computer can also vouch for a device it already approved. No other HTTP endpoint approves an owner.

The usual Bearer credential is still required after approval. Owner credentials are additionally bound to the verified Tailscale user and node on HTTP and WebSockets. Do not proxy these endpoints through a generic TCP listener or trust caller-provided identity headers. Guest and agent enrollment APIs remain separate.

### Live device presence

`WS /ws/presence` uses the existing private transport, Host/Origin validation, Funnel rejection, and Tailscale identity verification. Authenticate within five seconds with `{type:"auth",token,kind:"phone"|"tablet"|"computer"}`. `kind` is presentation metadata, never an authorization or identity claim. Tokens are sent in the first message, never in URLs. No command or control capability is conferred by this socket.

The server sends `{type:"presence",devices:[{id,name,kind,self,activity,access:[{kind,expiresAt}]}]}` when the snapshot changes. Activity is `connected`, `viewing`, `controlling`, or `terminal`, derived from live channels and control leases. Owners see live participants; restricted clients only see their own device. Tailscale-bound credentials group by a hash of verified user/node identity; otherwise IDs are credential-local. Closed connections leave the snapshot; duplicated tabs do not inflate counts. Credentials are rechecked every two seconds, deletion closes their sockets, and ping/pong checks detect dead connections within about twenty seconds. This endpoint does not enumerate the tailnet or disclose saved, disconnected credentials.

Presence `access.kind` is `paired`, `invited`, or `agent`, derived exclusively from server-side credentials. A deduplicated node retains every distinct live grant kind/expiry; it is never silently promoted from invited to paired. Guest pages open a presence socket after redemption and close it when their session ends.

## Browser agent presets

`POST /api/agents/browser-invitations` is an owner operation. It accepts `{name, preset, ttlSeconds, transport, folders?, apps?, write?, hidden?, terminalIds?, standing?, fullControlVersion?}`. `preset` is `full`, `apps`, `files`, or `readonly`; `transport` is `tailnet` or `funnel`. Timed invitations last 60–86,400 seconds. Apps requires selected catalog entries; Files requires chosen folders and optionally `write:true`. Full control and Apps require a supervising owner device and available Mac desktop helpers. Consult `GET /api/agents/browser-options` for actual support and allowed durations; `standing` is the explicit Always-access choice.

Full control additionally requires `fullControlVersion:1`, confirming the unrestricted OS-account access described below. For example: `{name:"Trusted agent", preset:"full", fullControlVersion:1, ttlSeconds:900, transport:"funnel"}`. Missing, older or unknown consent versions are refused, including requests from a cached older invitation form. Existing Full control grants without this stored consent end on upgrade and appear with `needsInvitation:true`; editing, renewing or reopening one cannot widen its access. Create and approve a fresh invitation. Moving Apps into Full control also requires a new invitation; ordinary edits can retain an already consented Full grant or lower its access.

Browser presets currently require macOS. `GET /api/agents/browser-options` returns `protectedFilesSupported` for the native protected file helper and `desktopAvailable` for screen presets. On Linux and Windows, a new Files invitation returns 503 before creating credentials. Existing browser credentials also receive 503 for protected file operations; owner file APIs, Reach terminals and scoped command-line credentials are separate capabilities. `protectedFilesSupported:true` identifies platform support, not a guarantee that native compilation or OS permissions will succeed.

The agent claims the one-use invitation through `POST /api/invitations/redeem` with `{invitation}`. A 202 response supplies a powerless pending receipt: `{requestId, requestSecret, ...}`. The owner approves or denies `/api/agents/admissions/:requestId`; the claimant polls `POST /api/invitations/claims/:requestId/status` with `{secret: requestSecret}` to collect approved access. Browser Funnel enrollment uses the browser-bound signed gateway protocol instead; a public invitation is not an ordinary Bearer API credential. Use the supplied agent page to establish that transport.

Every browser operation rechecks the current grant. `GET /api/browser` returns its preset, permitted operations, expiry and credential-local root indices. These endpoints under `/api/browser` are available only when granted:

| Endpoint | Request / response |
| --- | --- |
| `GET /desktop/screen?maxWidth=2560` | JPEG bytes, `no-store`; supported widths 320–3840. Full control, Apps and Read only; Apps excludes other apps. |
| `GET /desktop/front` | Current app/window and whether it is blocked, terminal-like or secure. |
| `GET /desktop/apps` | Apps this session may open. Full control and Apps only. |
| `POST /desktop/open` | `{app}` using a returned app path. Opens or raises it; inspect a new screenshot. |
| `POST /desktop/input` | `{action}`: click/move/drag/scroll/type/key, with coordinates in `[0,1]`; preset and native target checks still apply. Use tool schemas for the exact shape. |
| `POST /files/change` | `{op,root,path,content?,to?}`; `op` is write/mkdir/rm/cp. A write supplies whole UTF-8 content up to 1 MiB; cp supplies `to`. Changes are immediate within granted folders. |
| `POST /shell` | Full control only: `{command,root,cwd?}`, returning a logged status, output and exit code. A blocked command is a result, not successful execution. |
| `GET /shell/history` | This credential's command history only. |
| `GET /files/search?root=0&q=term` | Find names in a shared folder. File list/read also use `/api/files` and `/api/files/text`. |
| `GET /terminals/:id` | Output of a specifically shared terminal; never permission to type into it. |

HTTP desktop refusals include `{error,kind,holder?,retryInMs?}` where `kind` can be `busy`, `paused`, `retry`, or `blocked`. Another agent's lease or a person using the Mac may require waiting; observing again resolves stale focus. Revocation invalidates access. Full control uses the owner's OS privileges for every app, page, file and command, including Reach itself. It has no content deny list, hidden-app exceptions or shell sandbox; its roots include the filesystem root. macOS permissions still apply. Preset actions need no separate per-action approval after admission. Earlier invitations still expose restricted terminal and selected-app routes with their own approval semantics; a pending command must be polled, not resubmitted. These credentials cannot call owner approval routes.

The browser bridge, `window.reach.listTools()` and `window.reach.callTool(name,args)`, and the stdio MCP catalog describe the same available tools. MCP encodes screenshot bytes as image content. `node scripts/agent-remote.mjs tools` and `call TOOL '{...}'` refresh current access before selecting a route. The generic `reach-agent` file/job CLI is a separate scoped-credential interface; see [AGENTS.md](AGENTS.md).

## Working across agents

Owner devices only, like every `/api/sessions` route. What each feature does, and its rules, is in [Working across agents](ACROSS_AGENTS.md).

- `POST /api/sessions/:agent/:id/move` accepts `resume: true` as well as `to`: the new chat is also told to keep going. The answer adds `resumed`, and `resumeError` when the move worked but that message couldn't be sent. Refused while Reach is paused.
- `POST /api/sessions/:agent/:id/messages` accepts `chats: [{agent, id}]` (at most three Codex, Claude Code or Gemini CLI chats, never the chat itself). Each one's latest exchange goes ahead of the message in a `<reach-chat>` block, followed by `## My request:`. The phone shows the message's own words and the chats' names.
- `GET /api/sessions/relays` lists relays: those waiting or sending, and those that ended in the last day. `GET /api/sessions` carries the same list as `relays`, and the presence socket's `sessions` revision changes with them.
- `POST /api/sessions/relays` sets one up: `{from: {agent, id}, steps, now, item, cwd?, postBack?}`. `postBack: true` (only from an OpenClaw chat) posts the last answer back to that chat's own one-to-one WhatsApp or Telegram destination; groups and channels are refused. `steps` holds one to three of `{kind: "build" | "review", agent: "codex" | "claude" | "openclaw", instructions?}`, `{kind: "send", to: {agent, id}, instructions?}` and `{kind: "back"}`; `back` needs a step before it. With `now: true` the first step sends at once from the chat's reply (`item`: one further up) and the answer includes `opened: {agent, id}`. Otherwise it waits for the chat's next reply. One waiting relay per chat. Refused while Reach is paused.
- `POST /api/sessions/relays` from an OpenClaw chat (`from.agent: "openclaw"`, `id` its session key) needs `cwd`: the folder where Codex or Claude Code works, since OpenClaw has none. OpenClaw steps run in a new Reach-made OpenClaw chat and never post to a channel (docs/ACROSS_AGENTS.md).
- `POST /api/sessions/relays` with `trigger: "usage"` and `priority: ["codex", "claude", "gemini", "openclaw"]` opts this chat into auto-continue for 24 hours. The unique ordered list must include the current provider and at least one other writable provider; omit `steps`, `now`, `item`, and `postBack`. On each confirmed usage-limit error, Reach checks current availability and moves the history to the first available provider not already in this continuation’s chain, then resumes. Uninstalled, signed-out, disconnected, out-of-usage, or unsupported destinations are skipped. Gemini is currently read-only and skipped; OpenClaw must support chat transfer and be connected. OpenClaw uses its own tools; on a later move back to Codex/Claude, the original project folder is restored. If no destination is available, the watch stops with an explanation. It persists across restarts and can be cancelled like a relay; a failed resume keeps the destination chat without retrying. Ordinary errors and stops do not trigger it. The older one-step `{kind: "build", agent}` form remains supported for a single Claude/Codex switch. Responses include `priority` when configured.
- `POST /api/sessions/relays/:id/cancel` cancels a waiting relay (`{cancelled}`; 409 while a step is sending).
- `POST /api/sessions/teams` starts a team chat: `{lead: "codex" | "claude", helpers, cwd, text, images, model, effort, speed, mode}`. `helpers` holds one or more of `codex` and `claude`, each once; the lead's agent can be a helper too. The lead starts as `POST /api/sessions` starts a chat (same folder, model and mode checks) and gets Reach's team tools. The answer is `{team, threadId}`. Refused while Reach is paused.
- `GET /api/sessions/teams` lists teams: active ones, and those stopped in the last day. Each has `{id, state, lead, helpers, cwd, title, left, tasks}`, and each task has `{id, helper, kind, title, chat, state, problem?}`. `GET /api/sessions` carries the same list as `teams`. `POST /api/sessions/teams/:id/stop` stops a team (`{stopped}`).
- A team's tools (`team_delegate`, `team_message`, `team_stop`, `team_roster`, defined in `server/agent-sessions/team-tools.mjs`) aren't HTTP routes. The lead's agent runs `scripts/team-mcp.mjs`, which reaches Reach on a Unix socket in its data folder (`team.sock`, mode 0600), sending the team's key from its key file (`teams/<id>.json`, mode 0600).
- `GET /api/sessions/activity` returns `{chats, overlaps, windowMs}`. `chats` holds Codex and Claude Code chats at work or written in the last 30 minutes (at most 12), each with the full paths of the files it changed in that time, newest first. `overlaps` holds each file more than one chat changed, with the chats and when.
- `GET /api/sessions/journal?since=<ms>` returns `{events, waiting, now}`. `events` lists ended turns (`finished` with `files` changed, `failed`, `usage`, `stopped`) and relay steps (`relayed`, `relay-stopped`) after `since`, newest first, kept seven days. `waiting` lists the chats waiting on you now.
- `GET /api/sessions/search?q=` returns `{results, partial}`: messages from Codex and Claude Code history files containing every word, newest first, three per chat at most, each `{agent, id, role, at, snippet, title, cwd, listed}`. `partial` means older files were still being read; they finish in the background.

## Workflows

Owner devices only, like every `/api/sessions` route; every write also needs the owner's own device (`kind: "device"`). What a workflow is, and its rules, is in [Workflows](WORKFLOWS.md).

- `GET /api/sessions/workflows` lists workflows (`{workflows}`): running and paused ones, and drafts and finished ones from the last week. Each is `{id, state, title, cwd, problem, createdAt, updatedAt, planner?, tasks}`, each task `{id, title, agent, kind, together, model?, effort?, state, chat?, problem?}` without its text. `GET /api/sessions` carries the same list as `workflows`, and the presence socket's `sessions` revision changes with them. `state` is `draft`, `running`, `paused`, `done` or `stopped`; a task's is `waiting`, `starting`, `working`, `done`, `stopped`, `skipped` or `uncertain`.
- `GET /api/sessions/workflows/:id` reads one in full, versioned like a chat (`?known=<version>` answers `{unchanged, version}`): each task adds `task` (what to do), `summary` and `files` once done; a draft adds `edited` and, when its planner has a newer plan than your edits, `proposal: {title, tasks}`.
- `POST /api/sessions/workflows` makes a draft: `{title, cwd, tasks}`. Each task is `{title, agent: "codex" | "claude", kind: "build" | "review", task, together, model?, effort?}`, at most 20 (`model` and `effort` as `GET /api/sessions/models` lists them; left out, the agent's default; a task stops at its start if its agent no longer offers them); a draft's task may leave `task` empty until Run. `cwd` is checked as a new chat's folder. The answer is `{workflow}`.
- `POST /api/sessions/workflows/plan` makes a draft its planner fills: `{agent: "codex" | "claude", cwd, text, images, model, effort, speed}`. The planner starts as a new chat in the folder that only reads, whatever mode is sent, and its plan becomes the draft's tasks when its reply ends with one in a JSON block. The answer is `{workflow, threadId}`. Refused while Reach is paused.
- `POST /api/sessions/workflows/:id` edits: `{title?, cwd?, tasks?}` (the whole list, each task with its `id` when it has one). A draft takes anything; a running or paused one only the tasks after the last that started (those keep their place, 409 otherwise), and each must say what to do.
- `POST /api/sessions/workflows/:id/run` runs a draft (each task must say what to do), from the device that sends it; each task start checks that device again. `…/resume` goes on after a pause that no stopped task explains. `…/stop` stops the tasks at work (`{stopped}`). `…/proposal` takes the planner's newer plan. `…/again` copies one as a new draft. `…/remove` deletes a draft or a finished one (409 while it runs). Run, resume and retry are refused while Reach is paused.
- `POST /api/sessions/workflows/:id/tasks/:task/retry` starts a stopped task again in a new chat; `…/skip` goes on without it; `…/done` counts it done with what its chat ends on (409 without a reply). Each answers `{workflow}`.
