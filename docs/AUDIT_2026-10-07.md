# Release audit — October 7, 2026

Reach is **not yet qualified for the requested complete open-source readiness claim**. This audit repaired confirmed defects and exercised the current app through automated tests, real HTTP/WebSocket and stdio clients, a real browser-agent task, and the installed Codex provider. Physical phones, production network transitions, real Reach desktop control and the remaining Claude native flows remain gates. Passing a test suite is not proof that every entry point or security property works.

The audit began in an older, uncommitted source snapshot. The actual repository was then located and the candidate was based on `main` at `7352311`. Results from the older snapshot were kept separately and are not counted as candidate qualification. Three agents divided security, provider synchronization, and CLI/API/browser workflows; the primary audit integrated changes, inspected the interface, built the release, reviewed local-work preservation, and recorded the demo.

## Defects repaired

| Area | Reproduced problem | Corrected behavior |
| --- | --- | --- |
| Upload limits | Sixteen simultaneous starts all passed a per-client limit of one. | Pending creations reserve capacity before filesystem awaits and release it on failure. |

## Security assessment

Testing used disposable files, credentials and processes, not attacks on third-party infrastructure or real secret contents. Coverage includes host/origin checks, pairing, invitation/admission ownership, signed gateway replay and path restrictions, guest/agent isolation, permission reduction, stale approval invalidation, symlink/hard-link boundaries, native sandbox enforcement, command cancellation and concurrent resources. Tests reproduce concrete defects before correction and check the intended boundary afterward.

**Full control is trusted account access, not confinement.** A synthetic penetration test read a protected temporary marker through the deliberately unsandboxed shell. Expanding a text deny list cannot prevent equivalent interpreter/path constructions. The owner invitation, generated agent prompt and security documentation now disclose that commands can reach sensitive files with the owner's rights. Recognized password controls, hidden apps and protected-window checks are useful desktop guardrails; they do not isolate that shell or make arbitrary selected browsers/IDEs safe for untrusted agents. Use a dedicated OS account/host when that separation is required.

OS focus, windows and titles can change around native actions. The new checks reduce specific races; they are not a transaction with the desktop or a guarantee against malicious app overlays, title spoofing, prompt injection, resource exhaustion or future provider changes. Independent security review and a live disposable-account adversarial pass remain advisable.

The PDF renderer pins PDF.js 6.4.299, newer than the fixes documented in the [2026 scripting advisory](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j) and [2024 evaluation advisory](https://github.com/mozilla/pdf.js/security/advisories/GHSA-wgrm-67xf-hhpq). It uses canvas rendering without a PDF scripting manager or interactive annotation/XFA layer. Native PDF-frame failures were reproduced before replacing them; complex scanned formats, accessibility and the physical-phone browser matrix still need broader acceptance.

Dependabot vulnerability alerts were enabled and verified. The repository remained private. GitHub rejected enabling secret scanning/push protection as unavailable for this repository; branch-protection access was plan-restricted, and Code scanning was not enabled. No billing or visibility settings were changed. Establish these controls and private vulnerability reporting before broad public release.

## Preservation of local work

The original repository and both Claude worktrees were clean when inspected. Additional terminal, mascot and file-preview edits arrived in the supplied uncommitted checkout during the audit and were reconciled separately into the candidate rather than overlooked. Its three non-main local branches were all ancestors of main: `claude/busy-chatelet-e08e88` at `e101196`, `claude/zen-haibt-050e63` at `6910102`, and `reach-2026-10-04` at `f5b7580`. Their commit history is retained.

The 705-file snapshot captured during the audit is preserved as archival commit `3ecd9144c68d060c7988951ea80d4fe01d6304f8`; it includes an early Codex transport audit draft and is not described as a pristine pre-audit snapshot. Its older code is not copied over newer security/provider/preset behavior. The later 706-file checkpoint `410b5b4bd20ff6e15d06e34a771a83411a60d413` retains the concurrent terminal and preview edits as a child of that archival snapshot. A complete private Git bundle and a separate candidate-source archive were verified before reconciliation. The original checkout and ignored worksets remain intact locally; private saved worksets are backed up separately and are not release assets. Reconciliation reviewed manifest hashes and older provider, notification, browser and workspace implementations. Private working-copy/apply/discard code and sending through external OpenClaw channels were intentionally replaced by the newer security/product model; restoring them would regress that model.

Across 68 saved worksets, 1,235 of 1,244 distinct manifest-declared versions were recoverable, including one reconstructed from a saved patch. The recovered file and its reconciliation ledgers also have a separate checksummed private archive. Nine older intermediate versions were already absent from the available copies/history. These are provenance gaps, not proof of missing current functionality. The private reconciliation ledger records the exact unresolved hashes; no existing local work was deleted to conceal them. Consequently this report does not promise that every historical transient version has been recovered.

## Reproduce and finish qualification

Use Node 22 and the Go version in `tailnet/go.mod`:

```sh
npm ci
REACH_TEST_APP_NATIVE=1 REACH_TEST_FILE_BOUNDARY=1 REACH_TEST_SCRIPT_SANDBOX=1 npm test
npm run build:release
npm run package
npm run verify:package
node scripts/check-release.mjs
```

Native flags above apply to macOS. Run the separate live tests from a process with the required OS permissions and a signed-in Claude account: `npm run test:typing` and `npm run test:claude-native`. Follow [physical acceptance](RELEASE_TESTING.md), record the final commit/artifact checksum with results, and keep failures visible. Review the [release procedure](RELEASE.md) before publishing. Resolve personal history metadata without losing source work; a coordinated history rewrite is distinct from a normal fast-forward update.

The new README demo is a roughly 25-second MP4 and 24-second GIF composed from actual browser captures with synthetic data, labeled throughout. It includes Home, Files, Chat, a conversation, More, Settings and agent presets. It is suitable as an interface tour, not as evidence of live remote-desktop performance or universal synchronization.
