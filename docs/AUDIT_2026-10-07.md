## Security assessment

Testing used disposable files, credentials and processes, not attacks on third-party infrastructure or real secret contents. Coverage includes host/origin checks, pairing, invitation/admission ownership, signed gateway replay and path restrictions, guest/agent isolation, permission reduction, stale approval invalidation, symlink/hard-link boundaries, native sandbox enforcement, command cancellation and concurrent resources. Tests reproduce concrete defects before correction and check the intended boundary afterward.

**Full control is trusted account access, not confinement.** A synthetic penetration test read a protected temporary marker through the deliberately unsandboxed shell. Expanding a text deny list cannot prevent equivalent interpreter/path constructions. The owner invitation, generated agent prompt and security documentation now disclose that commands can reach sensitive files with the owner's rights. Recognized password controls, hidden apps and protected-window checks are useful desktop guardrails; they do not isolate that shell or make arbitrary selected browsers/IDEs safe for untrusted agents. Use a dedicated OS account/host when that separation is required.

OS focus, windows and titles can change around native actions. The new checks reduce specific races; they are not a transaction with the desktop or a guarantee against malicious app overlays, title spoofing, prompt injection, resource exhaustion or future provider changes. Independent security review and a live disposable-account adversarial pass remain advisable.

The PDF renderer pins PDF.js 6.4.299, newer than the fixes documented in the [2026 scripting advisory](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j) and [2024 evaluation advisory](https://github.com/mozilla/pdf.js/security/advisories/GHSA-wgrm-67xf-hhpq). It uses canvas rendering without a PDF scripting manager or interactive annotation/XFA layer. Native PDF-frame failures were reproduced before replacing them; complex scanned formats, accessibility and the physical-phone browser matrix still need broader acceptance.

Dependabot vulnerability alerts were enabled and verified. The repository remained private. GitHub rejected enabling secret scanning/push protection as unavailable for this repository; branch-protection access was plan-restricted, and Code scanning was not enabled. No billing or visibility settings were changed. Establish these controls and private vulnerability reporting before broad public release.

## Reproduce and finish qualification

Use Node 22 and the Go version in `tailnet/go.mod`:

```sh
npm ci
REACH_TEST_APP_NATIVE=1 REACH_TEST_FILE_BOUNDARY=1 REACH_TEST_SCRIPT_SANDBOX=1 npm test
npm run build:release
npm run package
npm run verify:package
node scripts/check-release.mjs
```

Native flags above apply to macOS. Run the separate live tests from a process with the required OS permissions and a signed-in Claude account: `npm run test:typing` and `npm run test:claude-native`. Follow [physical acceptance](RELEASE_TESTING.md), record the final commit/artifact checksum with results, and keep failures visible. Review the [release procedure](RELEASE.md) before publishing. The owner explicitly requested authorship changes, including already merged commits. The rewrite verifies every parent relationship, message, timestamp and unchanged blob, with only the two whitelisted historical comment-line redactions. Private backups are retained. Other clones must follow the rewritten main; do not merge obsolete history back into the publication branch. A main rewrite does not erase old pull-request refs, Actions logs or caches.

It includes Home, Files, Chat, a conversation, More, Settings and agent presets. It is suitable as an interface tour, not as evidence of live remote-desktop performance or universal synchronization.
