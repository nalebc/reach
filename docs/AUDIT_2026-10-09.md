# Agent access security audit — 2026-10-09

Scope: everything an invited agent can use to reach this Mac. Four read-only reviews ran in parallel; every finding below was traced in the code, and the fixed ones carry tests.

1. Admission and credentials (`server/core.mjs` createAuth, `server/agent-presets.mjs`)
2. The native helper's input policy (`scripts/native/agent-desktop.swift`, `server/agent-desktop.mjs`, `server/agent-guard.mjs`)
3. Server routes and the public gateway (`server/funnel-agent.mjs`, `server/index.mjs`, `server/browser-host-guard.mjs`, `server/browser-access.mjs`)
4. The Tools / MCP path and Tailscale join (`scripts/agent-remote.mjs`, `scripts/mcp-server.mjs`, `server/browser-tools.mjs`, `server/guest-keys.mjs`)

Threats considered: someone holding an invitation link or a copied credential; a malicious or prompt-injected admitted agent trying to escalate; another device on the tailnet; anyone on the internet reaching the public Funnel endpoint.

## What was checked and found sound

- Gateway: P-256 signed envelopes, exact keys, audience and ±60 s clock window, nonce consumed before any async step, token bound to the browser key's thumbprint, strict path normalization, generic error messages.
- Routes: each preset's complete allowlist, re-checked on every request and after every await; no preset reaches owner, agents, clients or settings routes; the new routes (describe, open-url, open by name) are scoped to the presets that may act.
- Admission: one owner-approved claim per invitation with a 6-digit code; approvals bound to one request id; receipts collected once; secrets 256-bit, compared in constant time, never logged.
- Mac helper: protected apps (password managers, Keychain, security prompts, Activity Monitor), Reach's windows and addresses, private System Settings panes and browser password pages are refused for pointer, keys, typing, app and website opening; password fields' values are never returned; typed text in terminals goes through the command deny list; vault values never go into a terminal and are never echoed.
- Tools path: invite keys single-use, tagged and short-lived; tool arguments validated against strict schemas; file paths re-checked on the server; the agent's local files are owner-only (0700/0600).

## Limits that stay

- Full control drives the Mac's own apps. An app an agent opens (Terminal included) runs outside the command sandbox; what the agent types into a terminal is checked by the command deny list only, which reads text. While the agent has access, the host guard refuses every owner request from this Mac and from any device but the approving one; the limit is what such an app leaves behind. Pause or end an agent you don't trust, and restart the Mac after a Full control session you're unsure of.
- A process on this Mac can still claim a device's identity on the private socket for the routes that need nothing more (a new approval request, which you see and decide). It can no longer get a credential that way.

## Conditions for "Always" access for Tools agents

1. The device's lifetime follows the agent's access on the server, not a client-sent value (today keys cap at 90 days while Always lasts 10 years).
2. Devices are removed by node ID on every way access ends (H4, M5, done).
3. A copied credential is detectable and recoverable: rotation with reuse detection, idle timeout, owner re-approval (M6).
4. Guest isolation is verified and stays verified (M7).
5. Moves and re-joins go through the owner's code approval (H3, done for links; Tools re-joins: H4/M5).
6. The Full control shell can't reach Reach itself (H1, done).

Until these hold, Tools invitations stay capped at 24 hours.
